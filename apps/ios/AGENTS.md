# iOS app

Rules for agents working in `apps/ios`, on top of the root [`AGENTS.md`](../../AGENTS.md).

- Quai's refusals become a `ConnectionError` in `QuaiErrorsMiddleware` only (from the answer's `_tag` and `message`), proxy refusals in `AccessHeadersMiddleware`. A call reads only its success with the generated throwing accessors (`try await client.listFixes().ok.body.json`, `.noContent`): no `switch` over an `Output`, no error message per route.
- Without a Mac, the `verify` skill's `ios` scenario (`.claude/skills/verify/ios/`) is the loop: `pnpm test` checks the contract for the generated client (`packages/api/test/ios.test.ts`), the CI generates it (`ios-client`, Linux), the preview server (`pnpm --filter @quai/cloud preview`: real Quai Cloud, fake Quai Home on the fixtures) serves the app, and the `ios` CI job builds, tests and posts screenshots of the views paired to it (`QuaiTests/AppScreenshots.swift`) (open the PR, a draft is fine: the CI runs on PRs only). A view change is done when its screenshot looks right.
- Swift is formatted by SwiftFormat (`apps/ios/.swiftformat`): run `apps/ios/scripts/format.sh` before pushing Swift; the CI's `swift-lint` job runs it with `--lint` and fails on a difference. SwiftFormat and SwiftLint are pinned in `apps/ios/tools.env` and run as static Linux binaries, no Swift toolchain needed: the scripts use the ones on PATH at those versions (an environment's setup script runs `apps/ios/scripts/install-tools.sh /usr/local/bin`), else download them into `apps/ios/.tools`.
- Swift is linted by SwiftLint (`apps/ios/.swiftlint.yml`, an explicit `only_rules` list): `apps/ios/scripts/lint.sh` must pass before pushing Swift (the CI runs it with `--strict`). Fix a violation rather than silence it; a real exception is `// swiftlint:disable:next rule - reason`.
